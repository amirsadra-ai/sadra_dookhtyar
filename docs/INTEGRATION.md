# دوخت‌یار — وب‌سایت معرفی

مستندات پیاده‌سازی، فایل‌های مهم و راهنمای انتشار (سرور یا GitHub Pages).

---

## ۱) معماری کلی

یک وب‌سایت معرفی و بازاریابی کامل، فارسی و راست‌چین برای محصول «دوخت‌یار» — بدون بکاند:

- **هویت بصری اختصاصی** هماهنگ با خودِ برنامه: مشکی عمیق `#0B0B0D`، طلایی محدود `#D6B46A`، بون گرم `#F5F2EB`، فونت وزیرمتن (نسخه محلی، بدون CDN).
- **بخش‌های صفحه اصلی:** هدر چسبان با منوی موبایل، Hero سینمایی با عنوان تایپ‌شونده، مسئله‌های واقعی خیاط، امکانات (چیدمان نامتقارن bento)، نمایش برنامه (۴ تب تعاملی)، نحوه شروع (۵ مرحله)، چرا دوخت‌یار، سؤالات متداول، فرم درخواست + دعوت نهایی، فوتر.
- **دریافت درخواست با پیامک گوشی (بدون سرور):** کاربر فرم را پر می‌کند و با زدن «ثبت درخواست» برنامه پیامک گوشی‌اش باز می‌شود؛ متن درخواست به‌صورت کامل و آماده در کادر پیام نوشته شده و فقط دکمه ارسال را می‌زند. گیرنده پیامک: شماره پشتیبانی محصول (در `demo-cta.tsx` قابل تغییر).
- **هیچ داده‌ای به سرور ارسال نمی‌شود؛** هیچ لاگ یا سرویس خارجی درگیر نیست. ارسال نهایی پیامک با خود کاربر است.
- **محتوای صادقانه:** همه قابلیت‌های معرفی‌شده از روی کد واقعی محصول استخراج شده‌اند. هیچ آمار یا نظر جعلی‌ای وجود ندارد.
- **دسترس‌پذیری و سئو:** HTML معنایی، aria و roleها، فوکوس‌پذیری با صفحه‌کلید، کنتراست مناسب، `prefers-reduced-motion`، متادیتای کامل فارسی + Open Graph، favicon اختصاصی.
- **موبایل‌محور:** تمام بخش‌ها برای نمایشگرهای کوچک طراحی و با Browser واقعی در عرض ۳۹۰px و دسکتاپ ۱۴۴۰px تست شده‌اند.

## ۲) جریان فرم درخواست (پیامک)

```
پر کردن فرم (نوع درخواست، نام، موبایل، شهر؟، فعالیت؟، توضیحات؟)
        │
        ▼
اعتبارسنجی کلاینت (نام ≥ ۳ نویسه، موبایل با نرمال‌سازی ارقام فارسی/عربی و +98)
        │
        ▼
ساخت متن پیامک — src/lib/sms.ts → buildSmsBody()   (فیلدهای خالی حذف می‌شوند)
        │
        ▼
ساخت پیوند sms: — src/lib/sms.ts → buildSmsUrl()
   اندروید:  sms:+989330592412?body=<متن URL-encoded>
   iOS:      sms:+989330592412&body=<متن URL-encoded>
        │
        ▼
کلیک روی پیوند پنهان داخل همان رخداد کاربر → باز شدن برنامه پیامک با متن آماده
        │
        ▼
صفحه موفقیت: شماره گیرنده + «باز کردن دوباره پیامک» + «کپی متن پیامک» (پشتیبان)
```

### الگوی متن پیامک

```
سلام، وقت بخیر.
من {نام و نام خانوادگی} هستم، از شهر {شهر}.        ← بدون شهر فقط «من … هستم.»

از طریق سایت دوختیار با این نرم‌افزار آشنا شدم و {جمله نوع درخواست}

زمینهٔ فعالیت من {نوع فعالیت} است.                  ← فقط اگر انتخاب شده باشد

توضیحات من:                                        ← فقط اگر نوشته شده باشد
{متن کاربر با حفظ کامل خطوط و نیم‌فاصله‌ها}

لطفاً برای ادامه و راهنمایی در این زمینه با من هماهنگ کنید.
با تشکر
```

جمله‌های ثابت نوع درخواست (دقیقاً مطابق انتخاب کاربر):

| انتخاب فرم | جمله در پیامک |
|---|---|
| درخواست دمو | «برای درخواست دمو و آشنایی با امکانات نرم‌افزار پیام می‌دهم.» |
| مشاوره | «برای دریافت مشاوره دربارهٔ نرم‌افزار پیام می‌دهم.» |
| نصب و راه‌اندازی | «برای نصب و راه‌اندازی نرم‌افزار پیام می‌دهم.» |

قواعد مهم پیاده‌سازی‌شده در `src/lib/sms.ts`:

- شهر/فعالیت/توضیحاتِ خالی → کل جمله حذف می‌شود (هیچ «نامشخص» یا مقدار خالی‌ای در متن نیست).
- توضیحات چندخطی با حفظ کامل خطوط، نیم‌فاصله (U+200C) و علائم می‌آید؛ فقط فاصله‌های اضافی و بیش از یک خط خالی متوالی مرتب می‌شود.
- شماره موبایل عمداً در متن پیامک تکرار نمی‌شود (گیرنده آن را از خود پیامک می‌بیند).
- متن با `encodeURIComponent` کد می‌شود؛ حروف فارسی، `%0A` (خط جدید) و `%E2%80%8C` (نیم‌فاصله) سالم منتقل می‌شوند.
- هیچ پیامکی به‌صورت خودکار ارسال نمی‌شود؛ دکمه ارسال با کاربر است.

## ۴) اجرا و انتشار

```bash
npm install        # یا bun install

npm run dev        # اجرای محلی روی 3000

npm run build      # بیلد سروری (standalone) + next start

# نسخه استاتیک برای GitHub Pages و هر هاست ساده:
STATIC_EXPORT=1 npm run build     # خروجی در پوشه out/
```

### انتشار روی GitHub Pages

1. بیلد استاتیک بگیرید: `STATIC_EXPORT=1 npm run build` → محتوای `out/`.
2. اگر سایت زیر زیرمسیر منتشر می‌شود (`username.github.io/nama-repo/`)، هنگام بیلد `NEXT_PUBLIC_BASE_PATH=/nama-repo` را هم بدهید:
   ```bash
   STATIC_EXPORT=1 NEXT_PUBLIC_BASE_PATH=/nama-repo npm run build
   ```
   برای دامنه اختصاصی یا صفحه کاربر (`username.github.io`) نیازی به BASE_PATH نیست.
3. محتوای `out/` را روی شاخه `gh-pages` (یا پوشه `/docs` طبق تنظیمات Pages) بگذارید؛ یا از GitHub Action استاندارد «Deploy static content to Pages» استفاده کنید.

چون دریافت درخواست کاملاً سمت کاربر و از طریق برنامه پیامک گوشی است، هیچ بکاند، پایگاه داده یا API کلیدی لازم نیست و صفحه روی هر هاست استاتیک کار می‌کند.

- ✅ `bun run lint` بدون خطا و بیلد پروداکشن (سروری و استاتیک) موفق
- ✅ تست واحد متن پیامک برای هر ۵ سناریوی مصوب + موارد مرزی (۲۶ بررسی): جمله دقیق هر نوع درخواست، حذف کامل جمله‌های فیلدهای خالی، حفظ نیم‌فاصله/خطوط/علائم در توضیحات چندخطی، عدم درج شماره موبایل و مقادیر undefined/null
- ✅ پیوند `sms:` — جداکننده درست برای iOS (`&body`) و اندروید (`?body`)، برگشت‌پذیری کامل کدگذاری، ارسال خودکار انجام نمی‌شود
- ✅ تست مرورگری end-to-end (موبایل ۳۹۰px + دسکتاپ ۱۴۴۰px): پر کردن فرم ← «ثبت درخواست» ← ساخته شدن پیوند `sms:` با گیرنده و متن صحیح ← صفحه موفقیت ← «باز کردن دوباره پیامک»
- ✅ اعتبارسنجی: فرم خالی خطاهای فارسی می‌دهد و هیچ پیوندی نمی‌سازد
- ✅ همان تست end-to-end روی بیلد استاتیک (`out/`) هم موفق — اثبات کارکرد بدون بکاند
